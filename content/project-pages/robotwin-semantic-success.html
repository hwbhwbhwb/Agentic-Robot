Project 03 / RoboTwin 2.0 / Simulation

Origin meets Semantic.
Different meanings of success.

One RSI-developed policy artifact is frozen for each task. Every rollout is then judged twice: once by RoboTwin's native Origin checker and once by a language-aligned Semantic checker.

The comparison isolates the evaluator. It does not compare two policies, and an 18-rollout difference is evaluator disagreement—not policy improvement.

Evaluation protocol

Develop once. Judge twice.

RSI may use evaluator feedback while developing code. The boundary becomes strict before measurement: freeze one artifact, run new seeds, and apply both definitions to the same rollout.

  1. 01
    Generate

    Write a task policy from the instruction and available interfaces.

  2. 02
    Iterate

    Use development feedback to revise the policy artifact.

  3. 03
    Freeze

    Select one artifact and stop coding-agent edits.

  4. 04
    Evaluate

    Run the same frozen policy on new seeds and record both Booleans.

How to read the result

A semantic fix is an audit layer, not a renamed benchmark score.

Origin-SR remains visible for historical comparison. Semantic-SR asks whether the instruction was completed through task-relevant physical evidence. The useful signal is not simply which number is larger, but where the labels diverge and why.

The semantic fix is open source, but task predicates can still contain omissions. We welcome the community to inspect the definitions, challenge edge cases, and improve them together.
